# ViaCRM SEO report

Audit date: 14 November 2026 · Site: https://viacrm.in · Branch: `worktree-seo-pass`
(not deployed, not merged)

## Summary

Before this change, the live site sent search engines one 696-byte HTML shell
for **every** URL. `robots.txt`, `sitemap.xml`, `/favicon.ico`, `/login`,
`/app/*` and made-up URLs all returned the homepage with HTTP 200. There was no
structured data, no social preview and only one indexable page, whose content
needs 577 KB of JavaScript to appear. The homepage's "Let's talk" section also
showed *"Contact details are being configured"*, so a visitor had no way to
contact you.

This branch adds:

- real `robots.txt` and `sitemap.xml` files
- true 404s
- `noindex` on the app, login and enquiry-form pages
- full meta, Open Graph and structured data
- seven fast, JavaScript-free keyword pages (four landing pages, a blog index
  and two articles)
- links to those pages from the homepage
- an Instagram contact fallback

## What I found (live site, before)

| Area | Finding | Severity |
|------|---------|----------|

| sitemap.xml | Missing. It also returned the SPA HTML. | High |
| Soft 404s | Every unknown path returned 200 with the homepage, which wastes crawl budget and creates duplicate content. | High |
| Indexability | `/login`, `/app/*` and `/enquiry/*` (customers' lead forms) were indexable, with no `noindex`. | High |
| Content | One page. The H1 "One workspace. Every opportunity." has no keyword. Crawlers that don't run JS (Bing partly, all social previewers) saw an empty `<div id="root">`. | High |
| Conversion | `/api/public` reports `contact_configured: false`, so the homepage shows no phone or email. | High (business) |
| Meta | Title "ViaCRM — Every lead. A way forward." has no keyword. The description was OK but generic. There was no canonical. | Medium |
| Social | No Open Graph or Twitter tags, and no share image. Links pasted in WhatsApp, LinkedIn or Instagram DMs showed no preview. | Medium |
| Structured data | None: no Organization, WebSite or SoftwareApplication. | Medium |

## What I changed (this branch)

### Crawl and index control (`infra/nginx.conf`)

- Explicit SPA routes: `/`, `/login`, `/app`, `/app/*`, `/enquiry/*`. Every
  other path must be a real file or a page directory, or it returns a real
  **404** with a branded `404.html`.
- `X-Robots-Tag: noindex, nofollow` on `/app`, `/login` and `/enquiry/*` (matched
  on `$request_uri`, so it survives the SPA fallback). `noindex` on
  `/index.html` and `/brand/*` (the brand preview page).
- `absolute_redirect off`, so `/blog` → `/blog/` redirects stay relative and
  keep Caddy's HTTPS origin.
- `/site/` CSS cached for 7 days.
- `/api/*`, `/assets/*` and `/release.json` are unchanged. API 404s are
  untouched (no `proxy_intercept_errors`), so the Android client's CRM error
  codes are preserved.

### Files in `web/public/`

- `robots.txt`: allows everything except `/app/` and `/api/`, and points to the
  sitemap.
- `sitemap.xml`: 8 URLs.
- `404.html`
- `og-image.png` (1200×630), `logo-512.png`, `apple-touch-icon.png`. The share
  image source is `web/seo/og-image.svg`.
- Static landing pages (no JavaScript, about 1–2 KB CSS, one H1, canonical,
  OG/Twitter, BreadcrumbList, WebPage/BlogPosting and FAQPage JSON-LD):

| URL | Primary keywords |
|-----|------------------|
| `/real-estate-crm/` | real estate CRM India, CRM for real estate brokers/agencies |
| `/property-dealer-crm/` | property dealer CRM, property dealer software; Hinglish copy plus a Hindi section (प्रॉपर्टी डीलर CRM) |
| `/real-estate-lead-management/` | lead management software (real estate), IndiaMART/Justdial lead integration |
| `/call-recording-crm/` | CRM with call recording, telecaller CRM, Android call recording CRM |
| `/blog/` | blog index |
| `/blog/real-estate-lead-follow-up/` | how to follow up real estate leads |
| `/blog/excel-vs-crm-for-property-dealers/` | Excel vs CRM, CRM for property dealers |

- The pages are generated by `web/scripts/seo-pages.mjs` from
  `web/seo/pages.mjs`. To edit copy or add a page, change `pages.mjs`, then run
  `node scripts/seo-pages.mjs` from `web/` and commit the output. The sitemap
  updates automatically.
- Every feature claim was checked against the backend: IndiaMART polling,
  Justdial webhook, Google Ads lead-form webhook, website form, CSV import with
  duplicates, Android call/recording sync limits, roles, leave/payroll, and AWS
  Mumbai hosting. There are **no WhatsApp claims and no prices.**

### SPA shell (`web/index.html`)

- Title "ViaCRM — Real Estate CRM for Indian Brokers & Agencies", plus a keyword
  description and `lang="en-IN"`.
- Canonical to `https://viacrm.in/`, Open Graph and Twitter large-image tags.
- JSON-LD `@graph` with Organization (logo, Instagram `sameAs`), WebSite and
  SoftwareApplication (feature list, no fake offers or ratings).
- A `<noscript>` fallback with links to the static pages.

### Homepage (`web/src/main.tsx`, `style.css`)

- The pill text is now "A real estate CRM for Indian brokers & agencies", and
  the hero paragraph mentions property dealers, brokers and agencies. The H1
  design is unchanged.
- Restores the homepage title and description after client-side navigation
  back from `/login`.
- A "Guides" nav link to `/blog/`. Footer links go to all four landing pages,
  the blog and Instagram (plain `<a>`, because they are outside the SPA router).
- When contact details are not configured, the page shows **"Message us on
  Instagram"** and **"Customer login"** buttons instead of a dead end.
- Updated tests: `tests/branding.spec.ts` (new title) and `tests/crm.spec.ts`
  (contact fallback).

   LinkedIn Post Inspector and the Facebook Sharing Debugger. Run the Google
   Rich Results Test on `/real-estate-crm/`.
5. **Google Business Profile.** See `docs/seo/backlinks.md` #2.
6. **Backlinks:** work through `docs/seo/backlinks.md` in priority order.

## Recommended next (code, for ViaCRM 1)

- **Split the homepage bundle.** Lazy-load the `/app` page modules
  (`React.lazy` for `pages-*`), so the public homepage stops downloading the
  whole CRM. That would roughly halve or better the 577 KB of JS. I didn't do
  it here because it touches every app route and its Playwright suites.
- **Prerender the homepage** HTML at build time, so non-JS crawlers and link
  previews see real text. This is less urgent now that the static landing pages
  exist.
- Add `/favicon.ico` (it returns 404 now; harmless but noisy in logs).
- Add the YouTube channel URL to Organization `sameAs` once it exists.
- Publish pricing on the site when decided. "Real estate CRM price India" is a
  high-intent search.

## Keyword notes

- The site positions ViaCRM as a **real estate** CRM. That matches the product
  and the target of brokers and agencies first. Generic "CRM for small business
  India" is extremely competitive (Zoho, HubSpot, LeadSquared). Pages for it
  would not match the product's real-estate UI. Win the real-estate niche
  first.
- **"WhatsApp CRM" was deliberately not targeted.** WhatsApp is excluded from
  ViaCRM (`AGENTS.md`). A page for that keyword would mislead visitors and
  bounce them.
- Hindi/Hinglish: `/property-dealer-crm/` targets Hinglish queries such as
  "property dealer ke liye CRM" and Devanagari queries. The Hindi YouTube
  shorts (ViaCRM 4) should link to it.
- Next content ideas, all true to the product:
  - "IndiaMART lead integration with CRM" (how-to)
  - "Site visit management for real estate"
  - "Telecaller performance tracking"
  - "How to import Excel leads into a CRM"
